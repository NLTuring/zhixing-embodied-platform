# 知行 · 交互原型

银白实验室风格的桌面 Web 工作台，包含任务工作台、机器人能力、技能库和实验记录。界面采用 16–17 px 的主要操作文字、14 px 的辅助文字，并为笔记本宽度提供动作计划抽屉。

## 本地运行

需要 Node.js 22.12+，建议 Node.js 24。首次进入 `web` 目录执行：

```powershell
npm.cmd ci
npm.cmd run dev
```

打开 <http://127.0.0.1:5173/>。机器人资源已随项目提供，无需重新转换。开发服务器仅监听本机；端口占用时会明确报错。

```powershell
npm.cmd run build
npm.cmd run preview
```

上述命令生成 `dist` 并预览生产版本。

## 体验路径

1. 默认任务是“把蓝色杯子放进右侧柜子”。开始验证后，柜口障碍会触发诊断，自动模式将提高接近高度并重新验证。
2. 切换“审核”模式，可在碰撞处暂停，阅读原因后应用修复。修复后可查看计划差异和路径示意。
3. 在“示例任务”中体验正常收纳、碰撞修复、缺失开门前置条件、双杯有序收纳。
4. 编辑、增删或拖动动作步骤，查看依赖检查；点击动作或拖动时间轴查看对应姿态。
5. 点击场景对象指定杯子，选择放置区域后拖动目标或调整偏移。环境设置还可控制障碍、柜门初始状态和修复预算。
6. 在机器人页面调整示例负载、工作范围，导入或导出能力 JSON；在技能库筛选动作、设置默认时长或插入当前计划。
7. 成功验证会自动保存实验，草稿可手动保存。历史记录支持搜索、筛选、回放、复制及 JSON 导出。

空格播放/暂停，Ctrl + Enter 生成计划。三维视图支持旋转、缩放、恢复视角和全屏。

## 已实现的范围

- 指令解析支持蓝杯、白杯、两个杯子的收纳顺序，以及避障和关门要求。
- 8 项技能覆盖识别、开门、抓取、接近、放置、松开、关门和归位。
- 本地规则检查动作依赖、持物状态、参数范围、负载与目标范围；柜口碰撞是由接近高度触发的确定性示例。
- 动作按时间连续采样，使用逆运动学驱动连续蒙皮骨骼；拖动时间轴会重建物体状态。肩、肘、腕中心按原模型机械关节重新定位，表面权重沿网格连接计算，避免切片旋转造成的断口和胸甲拉伸。
- 收纳柜位于机器人前方，采用侧滑门；起手先抬高再前伸，放置后先撤回再下落。肘部保持外侧且自然下沉，手掌朝向随动作平滑变化。柜内目标偏移限制为 ±5 cm，桌面、杯子、柜内目标共同适配约 51 cm 的手臂长度。
- 实验快照包含当前计划、修复前计划、场景、机器人能力、修复次数与运行状态。回放保留历史能力配置与修复差异，且不会自动创建重复记录；复制保留手工动作修改。
- 浏览器本地最多保存 50 条实验。无账号、云端同步或服务端数据存储，重要记录可导出 JSON。

这是可以操作的产品原型。尚未接入大模型规划服务、真实物理仿真器、真机控制或标定关节。碰撞检测与能力参数不能作为物理安全结论；轨迹对比是示意。蒙皮动画用于展示动作流程，未实现真实接触力、全身动力学或通用机器人适配。

## 验证

```powershell
npm.cmd test
npm.cmd run test:coverage
npx.cmd playwright install chromium
npm.cmd run test:e2e
```

单元测试覆盖计划生成、依赖检查、修复、时间轴状态重建、关节姿态和快照容错。覆盖率门槛针对 `domain.ts`、`motion.ts`、`robotPose.ts` 设置，不能解释为全应用覆盖率。几何回归较耗时，可独立运行；覆盖率快速检查使用 `npm.cmd run test:coverage -- --exclude src/clearance.test.ts`。

`clearance.test.ts` 直接加载 GLB，以蒙皮变形后的真实三角面检查全程姿态与柜板、柜门、滑轨、桌面的相交，包含 5 mm 检查余量。10 组场景以 0.06 秒步长涵盖单杯、双杯、目标偏移边界、初始开门与高低接近点，同时检查实际手腕与目标的偏差不超过 3 mm。`robotPose.test.ts` 检查待机绑定姿态、肘部外侧约束、腕部转角和每帧连续性；`robotSkin.test.ts` 检查抬臂时网格异常拉伸。该测试用于防止演示动画穿模，不等同于物理仿真或真机碰撞验证。

`node e2e/inspect-motion.mjs` 输出完整动作的多角度检查图；`node e2e/inspect-rig.mjs` 单独输出无遮挡的正面、侧面机器人姿态，避免柜体挡住变形问题。

Playwright 使用真实 Chromium/WebGL，覆盖完成保存、手动与自动修复、双杯任务、能力限制、技能编辑、实验复制/回放和三种桌面尺寸。失败截图及 trace 位于 `test-results`，可视化报告位于 `playwright-report`；验收截图输出到上级 `preview/runtime`。

```powershell
npm.cmd run format:check
```

## 模型转换

原始资源为 `../3Dmodels/机器人_obj.rar` 内的 OBJ、MTL 和贴图。转换脚本将原始约 148 万面简化为 8 万面，保留顶点颜色，由 `tools/skin_robot.py` 添加连续骨骼蒙皮。输出 GLB 约 3.04 MB；不再按面质心切割身体部件。

如需重新生成，在项目根目录运行（需要 Python、支持 RAR 的 `tar`）：

```powershell
py -m pip install numpy trimesh pillow scipy
py -m pip install --target tools/.asset-deps fast-simplification --no-deps
py tools/prepare_robot.py
```

输出为 `web/public/models/zhixing-robot.glb` 与 `robot-rig.json`。后者记录坐标系、几何数量及原型关节位置。

## 代码入口

| 文件                 | 作用                                   |
| -------------------- | -------------------------------------- |
| `src/App.tsx`        | 工作台交互与验证状态                   |
| `src/domain.ts`      | 任务解析、计划及约束规则               |
| `src/motion.ts`      | 可任意时间回放的连续动作采样           |
| `src/Scene.tsx`      | 三维环境与机器人关节驱动               |
| `src/sceneLayout.ts` | 柜板、滑轨、桌面和操作区域的共享几何   |
| `src/robotPose.ts`   | 机器人姿态求解，渲染与网格回归测试共用 |
| `src/SidePages.tsx`  | 能力、技能、实验记录页面               |
| `src/storage.ts`     | 本地快照校验、迁移和复制               |
| `src/styles.css`     | 视觉规范与响应式布局                   |

后续可将 `domain.ts` 的规则调用替换为规划/验证 API，并以经过标定的 URDF 或带蒙皮骨骼的资产替换演示关节。
