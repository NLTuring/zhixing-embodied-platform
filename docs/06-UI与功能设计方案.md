# 知行 UI 与功能设计方案

本方案面向真实科研与工程使用，规划一套以三维任务空间为中心的桌面 Web 工作台。第一版先制作完整交互原型，将任务输入、计划编辑、机器人动作、失败诊断与修复串成可操作的连续流程；后续沿用这套交互接入真实规划与仿真服务。

设计主张是：用户在同一工作区里看见任务、动作和结果的因果关系。视觉上的辨识度来自银白器械质感、清晰排版、空间中的目标与约束，以及修复前后可以直接比较的变化。

## 2 视觉与交互概念

### 2.1 银白实验台

三维场景铺在轻微冷灰的背景上，以柔和环境光、落地阴影和淡刻度建立空间感。机器人保留提供模型的外形与材质特征；桌面、柜子和杯子使用简洁、可信的材质，让目标物和动作路径容易辨认。

界面中的蓝色主要用于当前选择、主要操作、目标位置和修复路径。成功、警告、失败同时配合文字和图形标记。场景中只有与当前步骤有关的辅助信息展开，保持机器人和任务对象的可见性。

### 2.2 四个能体现产品价值的交互亮点

1. **空间中的任务标签。** 点击杯子、柜子或目标位置后，对象以标签进入自然语言输入区。悬停标签会高亮对应物体；目标位置修改后，同步更新任务约束。用户始终知道指令对应的是哪个对象。
2. **可以逐步阅读的动作序列。** 计划步骤、机器人动作和时间轴共享编号。点击某一步，会定位到对应时间与场景对象；修改技能参数时，预览受影响的目标或路径。
3. **失败位置上的解释。** 验证失败后，场景定格在问题发生的位置，显示碰撞接触点或不满足的约束。侧面说明发生在哪一步、判据是什么，以及建议修改什么。
4. **同一场景中的修复比较。** 原轨迹以灰色虚线显示，修复轨迹以钴蓝实线显示。拖动时间游标比较两版动作，必要时切换左右对照。计划列表同步标出新增步骤和参数变化。

重点是让这些交互在日常调试中有用。进入工作台后，首屏就能创建任务、选择对象和查看计划。

## 3 视觉规范

### 3.1 色彩

| 用途 | 建议色值 | 使用方式 |
| --- | --- | --- |
| 页面背景 | `#F4F6F8` | 大面积浅灰白 |
| 面板与输入区 | `#FFFFFF` | 承载正文和操作 |
| 场景背景 | `#EDF1F6` | 帮助区分物体、阴影与辅助线 |
| 主文字 | `#18212F` | 正文、标题、操作标签 |
| 次级文字 | `#536075` | 描述、时间、单位 |
| 主强调色 | `#2457E7` | 主操作、选择状态、修复路径 |
| 成功 | `#23735A` | 验证通过、步骤完成 |
| 警告 | `#96610C` | 待确认、约束风险 |
| 失败 | `#B93C48` | 失败步骤、接触点 |
| 边界 | `#DCE3EC` | 面板分隔、输入边界、表格线 |

阴影主要用于悬浮工具与场景标注。普通内容通过留白、浅边界和字重组织，减少多层嵌套面板。

### 3.2 字级与尺寸

中文优先采用清晰的系统黑体，Windows 下优先使用微软雅黑；数字保持等宽对齐，便于扫描参数。建议使用常规和中等字重建立层级。

| 内容 | 建议字号 |
| --- | --- |
| 页面标题 | 24–28 px |
| 面板标题 | 20–22 px |
| 任务输入、主要操作 | 17–18 px |
| 正文、动作步骤、导航 | 16 px |
| 时间戳、单位、辅助说明 | 14 px |

常用按钮高度为 42–46 px，编辑行高度为 48–56 px。面板内边距通常为 20–24 px。模型上的标注要限制数量，文字保持至少 14 px，并避免互相遮挡。

正文与底色对比度以至少 4.5:1 为目标。缩小窗口时优先改变布局和面板展开方式，保持正文与主要操作字号。

## 4 信息架构

首版一级导航只保留四个工作区域。

| 页面 | 核心问题 | 主要内容 |
| --- | --- | --- |
| 任务工作台 | 这个任务怎样完成，哪里失败，如何修复？ | 三维场景、任务输入、动作列表、时间轴、诊断与修复 |
| 机器人 | 当前本体具备哪些能力？ | 模型预览、技能适配、可达范围、关节与负载等能力描述 |
| 技能库 | 可调用什么动作，怎样使用？ | 技能前置条件、效果、参数、适用本体、版本 |
| 实验记录 | 以前运行了什么，结果能否追溯？ | 任务、场景快照、计划版本、执行轨迹、修复历史 |

导航切换保留未提交草稿。重新打开平台时可回到最近的工作台；首次使用提供一个已配置的桌面收纳场景，让用户立即进入核心流程。

## 5 任务工作台

### 5.1 布局

工作台由顶部环境栏、一级导航、中央三维场景、右侧计划与诊断面板、底部任务输入和时间轴组成。

顶部显示当前任务、机器人、环境与运行状态。中央场景占主要空间。右侧默认展示动作列表，选中动作后展开参数；诊断和修复发生时，相应内容就地呈现。底部保持任务输入与时间轴位置稳定，便于反复实验。

### 5.2 不同窗口宽度

| 宽度 | 布局建议 |
| --- | --- |
| 1600 px 及以上 | 三维场景与 360–400 px 的计划面板并排；诊断可以随当前步骤展开 |
| 1280–1599 px | 保留场景与约 340 px 的计划面板；参数和详细诊断使用可展开区域 |
| 1024–1279 px | 计划或诊断采用单一侧面抽屉，按需打开；任务输入和主要运行控制保持可见 |
| 更窄的窗口 | 三维场景与工具区分区显示，保留正常字号；精细编辑提示切换到更宽窗口 |

笔记本高度有限时，时间轴可收为单行，详细轨迹按需展开。避免把所有工具同时压进首屏。

### 5.3 场景交互

- **选择：** 点击物体查看名称、状态和可用技能，并将对象加入任务。
- **目标设置：** 点击合法表面或拖动目标标记；预览放置区域、占用空间与约束。
- **相机：** 旋转、平移、缩放，以及恢复默认视角、聚焦当前步骤。
- **编辑模式：** 明确区分选择、移动对象和相机操作，避免拖物体时意外旋转视角。
- **约束显示：** 可达范围、路径、接触点与目标区域按当前步骤显示，也可手动切换。

拖动目标会先产生草稿预览，松开后更新任务约束。与当前计划冲突时，在对应动作中提示；执行中的场景修改进入新草稿，暂停或停止当前执行后再应用。

### 5.4 任务输入

输入区支持场景范围内的自然语言任务，例如：

- 把蓝色杯子放进右侧柜子。
- 先打开柜门，再把两个杯子分别放到柜内的指定位置。
- 把杯子收进柜子，避开桌面上的障碍物，完成后关好柜门。

系统从输入中提取对象、目标、顺序和约束，显示为可检查的标签。对象存在歧义时要求选择具体对象；指令超出当前技能范围时说明可支持的部分，并提供修改建议。

约束冲突应定位到具体要求，例如“目标区已被占用”或“当前本体未适配此技能”。支持复制对象名称、撤回最近一次目标编辑和打开示例任务。

### 5.5 动作列表编辑

每一步包含编号、动作名称、对象、状态，以及可展开的参数与前置条件。用户可以增删步骤、调整顺序、替换兼容技能、修改位置和动作参数。

重排后检查前置条件、对象状态和技能依赖。冲突直接标在相关步骤中。替换技能时保留兼容参数，并明确指出需要重新设置的字段。

编辑形成新的计划版本。已经运行的版本保持可追溯，新草稿需要重新检查后才能执行。第一版使用动作列表，不提供完整节点图编辑。

## 6 一次完整任务的流程

1. **创建任务。** 选择桌面收纳场景与机器人，通过语言和场景选取指定杯子、柜子、目标区域及约束。
2. **生成计划。** 生成动作列表，显示对象与步骤关系。用户可以编辑后再次检查。
3. **执行前检查。** 检查前置条件、适配技能、目标占用和明显不可达等问题，定位到具体动作。
4. **开始验证。** 固定本次任务和场景快照，播放完整连续动作，同步更新步骤状态与时间轴。
5. **定位失败。** 在合法的安全状态停止，标出失败步骤、问题位置、判据与受影响范围。
6. **修复。** 自动模式在给定尝试预算内推进修复；审核模式先展示修改差异，再由用户应用。
7. **重新验证。** 回到满足条件的检查点，校验并重放受影响的动作段，保留原轨迹作比较。
8. **保存实验。** 保存任务、场景、计划版本、结果、轨迹与修复过程。

### 6.1 两类失败需要分别呈现

**执行前发现的问题。** 例如柜门关闭，而计划缺少开门步骤。已知前置条件未满足时，在检查阶段就应提示并补入动作，随后再执行。

**动作过程中暴露的问题。** 首个完整回放建议采用“移向柜内时，杯底与柜口下沿发生碰撞”。计划在语义和基本前置条件上成立，路径仍需要验证；修复通过增加接近点、调整高度或放置姿态来解决。

这种区分能清楚解释约束检查与仿真验证各自的作用。演示中至少保留正常通过、前置检查失败、运动验证失败并修复三条可完整走通的路径。

### 6.2 诊断与修复面板

诊断回答四件事：失败发生在哪一步、触发了什么判据、问题位于哪里、建议怎样修改。支持不可达、碰撞、抓取失败、前置条件不满足、超时和语义歧义等项目定义的类别。

修复卡片显示原版本与新版本、增加或修改的动作、参数变化、理由，以及受影响步骤。初版至少能清晰展示补入动作、调整参数和替换兼容技能三类变化。

自动模式提供尝试次数上限、停止条件和随时暂停。预算耗尽时保留所有尝试，显示仍未解决的原因。审核模式使用“应用修改并验证”作为主要操作，也支持返回手动编辑。

修复改变前序动作时，重新检查后续动作的依赖与状态。回放从合法检查点恢复，杯子、夹持关系、柜门角度和计划状态必须一致。

## 7 三维模型与动作设计

### 7.1 当前资产核实

`3Dmodels/机器人_obj.rar` 包含一个 OBJ、一个 MTL 和一张 JPEG 纹理。实际渲染确认是银灰色人形机器人，外形适合银白实验室方向。

原始 OBJ 约 110 MB，包含 737,680 条位置顶点记录和 1,475,442 个面，仅声明一个对象组。OBJ 本身未提供关节定义、骨骼动画、机器人控制接口、关节限位或负载数据。

网页使用前需要进行模型轻量化、材质整理、部件分离或骨骼绑定，并标定关节轴、手部抓取点和柜门接触动作。具体处理路线需在资产适配时验证，以保留现有模型的外形为目标。

### 7.2 动作连续性

首个动作序列建议包括定位目标、打开柜门、接近杯子、抓取、移动到柜口、放置、松开和归位。按任务要求可加入关闭柜门。

连续动作需要体现肩、肘、腕和手部的协调。抓取后杯子随手部移动，放置后解除夹持并保持在目标区域；柜门沿正确铰链转动。动作过渡与接触位置应稳定可辨认。

时间轴支持播放、暂停、逐步定位、拖动与速度调整。任意跳转后，物体位置、关节姿态、柜门状态、夹持关系与步骤状态要同步恢复。

比较模式只显示与当前问题相关的轨迹或淡化姿态，避免多个完整机器人同时遮挡场景。相机自动聚焦应平滑，并允许用户随时手动接管；减少动态效果设置下保留必要动作反馈。

### 7.3 原型与真实能力的界面边界

原型以明确的“原型演示”环境标识说明运行性质。自由任务在已支持对象与技能范围内组合，动画和结果基于该范围的一致规则。

OBJ 只负责几何与外观。机器人能力、可达范围和技能映射在原型中采用明确标注的示例配置；接入真实服务后，展示标定与接口提供的数据。示例数值不能作为项目实测指标。

后续接入真实服务时，任务、计划、状态和轨迹仍采用相同交互；需补充连接、排队、超时、取消和恢复等运行状态。

## 8 其他三个页面

### 8.1 机器人能力管理

页面以模型预览和能力清单组成。优先展示当前本体已适配的技能、缺失能力、标定状态及版本。关节、可达范围、负载与传感配置按需展开。

选择某个技能时，高亮对应执行部位和目标范围。用户可以查看兼容技能、编辑示例能力参数，并将本体用于新任务。真实能力数据应携带来源与标定版本。

本体导入入口区分几何资产和能力描述。缺少能力信息时允许预览模型，清楚标出待补充项。

### 8.2 技能库

以可扫描的列表展示技能名称、类别、适配本体、版本和状态。选择技能后，在详情中展示前置条件、效果、参数、风险、依赖和短动作预览。

首批建议包含识别目标、移动到接近点、抓取、放置、松开、打开柜门、关闭柜门、归位等桌面任务需要的技能。相似动作通过参数配置复用，减少重复条目。

支持搜索、筛选、查看历史版本、编辑参数默认值与插入当前计划。技能被修改后提示哪些草稿需要重新检查；历史实验仍引用当时的技能版本。

### 8.3 实验记录

以列表展示任务名称、运行时间、机器人、最终状态、修复轮次与执行时长。支持按本体、技能、状态和日期筛选。

打开记录进入原工作台的回放状态，恢复场景快照、任务与计划版本，显示失败位置和修改历史。支持复制为新任务和导出单次实验记录，帮助追溯与复现。

历史结果保留当时的数据；复制到新任务后形成独立草稿。单次实验的成功状态、耗时、失败原因与修复次数优先于缺少样本依据的统计指标。

## 9 状态与反馈

| 状态 | 界面反馈 | 用户可以做什么 |
| --- | --- | --- |
| 未创建任务 | 可操作默认场景、对象提示、示例入口 | 输入或选取对象 |
| 解析待确认 | 歧义对象或冲突要求就地标注 | 指定对象、修改要求 |
| 计划草稿 | 动作列表和检查状态 | 编辑、生成、检查 |
| 检查未通过 | 定位问题步骤与约束 | 手动编辑或应用建议 |
| 验证中 | 动作、步骤与时间轴同步 | 暂停、停止、调整回放视角 |
| 暂停 | 保留完整现场状态 | 继续、查看参数、另建草稿 |
| 验证失败 | 定格位置、原因与证据 | 修复、编辑、查看原轨迹 |
| 修复待审核 | 参数差异与受影响步骤 | 应用、修改或返回编辑 |
| 验证通过 | 目标完成与执行记录 | 保存、回放、复制任务 |
| 未找到可行方案 | 显示尝试与仍未解决的问题 | 调整目标、能力或预算 |

运行按钮文案随状态变化，避免多个同权重主操作。常用功能有明确按钮，快捷键用于提高效率：例如组合键生成计划、非输入焦点下空格暂停、Escape 取消当前场景编辑。

## 10 设计验收与后续顺序

视觉评审先检查静态概念图，再检查不同宽度下的场景占比、字级与面板展开方式。交互原型阶段优先走通三条完整任务路径，然后补齐机器人、技能与实验记录页面。

重点验收内容：

- 正文与主要操作字号保持清晰，笔记本上不靠缩小文字容纳功能。
- 语言对象标签与场景对象互相定位，修改目标后正确更新任务。
- 步骤重排或参数编辑能够提示具体冲突，版本与运行记录保持一致。
- 机器人伸手、抓取、开柜、移动和放置形成连续动作，接触与夹持关系正确。
- 时间轴跳转、暂停和恢复后，动作与物体状态同步。
- 执行前检查与执行中失败分别呈现，修复可以查看具体修改和前后路径。
- 自动修复有预算与停止状态，审核模式能手动编辑与重新验证。
- 每条历史记录能够回到原任务、场景与计划版本。
- 原型演示、真实运行及示例数据的性质清楚可辨。
