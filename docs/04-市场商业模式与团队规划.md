# 市场、商业模式与团队规划


## 第七章  市场分析

本章对应商业计划书的"市场分析"章节、PPT 的第 9 页。

铁律：不要引用第三方报告的大数字。市场规模的估算必须自下而上，即"全国有多少家目标客户 × 单客户席位或节点数 × 可触达比例 × 付费率 × 客单价"，这样评委才能检验逻辑，也才无法被一个提问击穿。


### 7.1 目标客户分层

| 层级 | 客户类型 | 需求特征 | 付费意愿 | 切入顺序 |
|---|---|---|---|---|
| 第一层 | 高校与科研院所的具身智能、机器人、人工智能实验室 | 需要可复现基准、跨本体技能复用与能定位失败原因的诊断工具；论文需要别人能重复的实验协议 | 中（预算有限，但对省时间极敏感） | ★ 首发滩头 |
| 第一层 | 具身智能与人形机器人整机厂商的算法团队 | 每换一款本体就要重做技能接口与评测脚本；需要快速对比不同规划模型的工程表现 | 高（直接节省研发工时） | ★ 现金流主力 |
| 第二层 | 国家级与地方具身智能创新中心、第三方检测机构 | 需要中立、可复现、可复核的测评手段与标准草案支撑 | 高（财政资金与专项经费） | 一期（标杆案例） |
| 第二层 | 工业与服务机器人集成商 | 项目交付前需验证任务流程的可行性与鲁棒性，需要可交付的验证报告 | 中高（按项目付费） | 一期 |
| 第三层 | 大模型公司的具身智能部门、云仿真与算力平台 | 需要把规划模型接入多种仿真与本体做规模化评测 | 高，但周期长 | 二期 |
| 第三层 | 职业教育与工程训练机构 | 需要可复现的教学实验平台与标准化实验包 | 中（采购周期长、单价低） | 二期（渠道复用） |


### 7.2 市场规模自下而上测算（框架，需填入实际调研数据）

| 测算项 | 取值 | 数据来源 / 说明 |
|---|---|---|
| 目标客户基数 A | 【待填】家 | 具身智能整机厂商与算法公司、开设具身智能方向的高校与科研院所、创新中心与检测机构、机器人集成商的数量；建议通过行业协会名单、教育部学科与实验室公开信息、企业公示信息交叉验证 |
| 单客户席位需求 B | 【待填】个席位 / 并发任务 | 按团队规模与评测频率估算，高校实验室与厂商算法团队差异较大，建议区分两档口径 |
| 可触达比例 C | 【待填】% | 通过开源社区、学术会议、创新中心与仿真器厂商渠道可触达的比例 |
| 付费转化率 D | 【待填】% | 建议保守取值 3%–8%；开源用户向付费用户转化的比例需给出依据 |
| 年度客单价 E | 【待填】元 / 席位 · 年 | 平台订阅 + 私有化部署摊销 + 评测服务的合计口径 |
| 可服务市场规模 | A × B × C × E | 自下而上推导，需写出完整计算过程与每一步的假设 |
| 三年目标市场份额 | 【待填】% | 建议保守取值，避免被追问细节 |

补充说明：建议在商业计划书中同时给出"自上而下"的行业规模作为背景，但决策依据必须用自下而上的测算，并明确标注哪些是假设、哪些是调研数据。本项目的客单价由"节省的研发工时"支撑，因此在测算时必须把"客户目前的评测与适配成本"作为参照基准一并给出。


### 7.3 切入策略：滩头战略

学生团队最常犯的错误是"面向所有机器人用户"。必须选一个痛点明确、效果可量化、决策链短的滩头市场，建立根据地后再扩张。

| 阶段 | 滩头目标 | 选择理由 | 成功标志 |
|---|---|---|---|
| 第一阶段 | 高校与科研院所的具身智能实验室 | 痛点最清楚：论文要可复现、换本体要重做、失败不知道为什么；决策链最短，一位老师或一位博士生即可决定试用；开源内核就能触达；而这批人未来会进入厂商，是最早的口碑来源 | 活跃实验室用户数、基于本平台发表的论文或公开实验、技能库的社区贡献数 |
| 第二阶段 | 整机厂商与人形机器人公司的算法团队 | 需求从"科研"转为"工程"：每一款新本体都要重做适配与评测，时间成本直接折算为研发投入；可用"接入工时下降"与"迭代周期缩短"量化 | 付费席位数量、接入工时下降实测、至少 1 家厂商的产品化采用 |
| 第三阶段 | 创新中心、检测机构与集成商，以及评测标准与认证服务 | 单项目金额高、竞争少；一旦评测协议成为准入口径，即形成标准壁垒；同时反向带动前两个阶段的客户 | 政府采购或测评服务合同、参与地方或行业标准制定 |

## 第八章  商业模式

本章对应商业计划书的"商业模式"章节、PPT 的第 9 页。


### 8.1 商业模式画布

| 画布模块 | 内容 |
|---|---|
| 客户细分 | 高校与科研院所的具身智能实验室、具身智能与人形机器人整机厂商的算法团队、国家级与地方创新中心及第三方检测机构、工业与服务机器人集成商、大模型公司的具身智能部门、仿真器与机器人软件厂商（作为渠道与被集成方） |
| 价值主张 | 对高校实验室：实验可复现、换本体不用重做、失败能被定位。<br>对整机厂商算法团队：新本体接入工时大幅下降，规划与评测迭代从"数天一轮"变成"数十分钟一轮"。<br>对创新中心与检测机构：拿到中立、可复现、可复核的测评手段与标准草案支撑。<br>对集成商：交付前有可交付、可复核的验证报告。 |
| 渠道通路 | 开源内核与社区（代码托管平台、学术会议、仿真器厂商生态）、高校实验室的种子用户与口碑、创新中心与检测机构的联合共建、行业展会与技术宣讲、仿真器厂商与机器人软件厂商的预装与合作 |
| 客户关系 | 自助式（开源内核降低门槛）+ 社区共建（技能库与基准贡献）+ 企业客户的专属技术支持与私有化交付 |
| 收入来源 | 平台订阅（评测席位与任务量）、企业版与私有化部署、标准化评测与认证服务、定制开发与联合基准建设 |
| 核心资源 | 技能抽象与验证修复闭环相关专利、技能库与失败模式库、标准化任务集与评测协议、跨领域团队（规划 + 机器人 + 大模型 + 平台） |
| 关键业务 | 内核研发与技能库维护、仿真器与本体适配、评测协议与榜单运营、社区与开源运营、企业与机构客户拓展、标准参与 |
| 重要伙伴 | 仿真器厂商与开源社区（适配与生态）、高校与科研院所（算法与验证）、创新中心与检测机构（标准与背书）、整机厂商（真机验证与需求输入）、云与算力服务商 |
| 成本结构 | 研发人力（学生团队成本优势）、算力与仿真软件许可、真机与耗材、社区与市场推广、知识产权与合规、差旅与学术活动 |


### 8.2 收入结构（四层，逐层提高客单价）

| 层级 | 产品形态 | 目标客户 | 定价 | 战略作用 |
|---|---|---|---|---|
| 开源层 | 开源内核与会话式工具（单机、单仿真器、有限任务量） | 高校实验室、个人研究者、学生 | 免费 | 获客与生态：把技能表示与评测协议先装进用户的工作流 |
| 平台层 | 评测云平台订阅（席位 + 任务量 + 并行度） | 高校课题组、厂商算法团队、集成商 | 【待测算】元 / 席位 · 年 | ★ 现金流主力：按年续费的稳定收入 |
| 企业层 | 企业版与私有化部署（本地评测集群、技能库与失败模式库管理、权限与审计） | 整机厂商、大型企业、创新中心 | 【待测算】元 / 项目或年 | 高客单价与高替换成本：数据留在客户本地，平台成为其研发流水线的一部分 |
| 服务层 | 标准化评测与认证服务、联合基准建设、定制适配 | 创新中心、检测机构、地方政府、大型企业 | 【待测算】元 / 次或项目 | ★ 公信力与标准壁垒：一旦成为测评口径，反向锁定前两层客户 |

收入结构的设计逻辑：开源层负责"铺得开"，平台层负责"收得回"，企业层负责"赚得多"，服务层负责"锁得住"——四层逐级提高客单价与替换成本，且共用同一套内核与技能库，边际成本极低。


### 8.3 定价策略与竞品对照

| 方案 | 价格口径 | 说明 |
|---|---|---|
| 知行（平台订阅 + 服务） | 【待测算】 | 学生团队人力成本优势 + 软件边际成本近零；开源层低价获客，以企业层与服务层获利 |
| 工程师手工适配与脚本（现状基线） | 【待填】元 / 人日 × 人日数 | 含工程师工时、真机占用与调试时间；需按"每新增一个本体"与"每次模型迭代"两种口径分别折算 |
| 商业仿真平台许可 | 【待填】元 / 年 · 节点 | 以公开报价为准，需截图存档并记录访问日期；注意区分训练用途与评测用途的授权差异 |
| 学术基准（开源） | 免费 | 开源但无企业级支持、无跨本体能力、无失败诊断与报告交付 |
| 第三方测评服务（现状） | 【待填】元 / 次 | 以人工测试为主的测评服务口径，用于对照我们的自动化评测 |

定价逻辑：与手工适配相比，我们的成本优势来自"技能库一次建模、多本体复用"；与现有仿真平台相比，我们的差异化在于"规划层与验证层"而非物理引擎，因此不与仿真软件做同质化的价格竞争，而是提供"手工做不了、仿真软件不覆盖"的能力。


### 8.4 增长飞轮（商业模式创新的得分点）

```
① 开源内核与免费工具触达高校实验室与个人研究者，降低使用门槛
        ↓
② 用户贡献技能、任务集与失败案例，技能库与失败模式库持续增厚
        ↓
③ 资产变厚 → 规划与诊断能力更强 → 评测结论更可信、更可比
        ↓
④ 可信度提升带来厂商算法团队与创新中心、检测机构的付费意愿
        ↓
⑤ 标杆客户与标准参与带来更多用户与更多真实数据
        ↓
⑥ 回到第 ② 步，飞轮加速运转
```

飞轮的关键在于：开源层不只是引流工具，它在持续收集真实世界里的技能实现、任务变体与失败案例，形成竞品拿不到的资产壁垒。仿真器厂商有引擎但缺少规划层资产与中立立场；整机厂商有需求但既有资产无法对外复用。

数据与许可合规声明（答辩可能被询问，必须在商业计划书中写明）：① 严格核查并遵守各仿真器与模型的开源 / 商业许可条款，在文档中提供许可清单与合规说明；② 用户的任务集、实验配置与真机数据默认归属用户，仅在明确授权后才用于基准建设，且支持随时撤回与删除；③ 不采集任何个人信息；④ 提供完全离线的本地部署模式，涉密与敏感场景可在不联网环境下运行。

## 第九章  财务预测

本章对应商业计划书的"财务分析"章节。

重要提醒：不要编造收入数字。学生项目在财务预测上被追问细节的概率极高，一旦答不上来就会全线崩塌。正确做法是给出清晰的单位经济模型（客单价、获客成本、毛利结构）与保守的客户数量假设，并明确标注哪些是假设、哪些是实际数据。


### 9.1 成本结构

| 成本项 | 内容 | 性质 |
|---|---|---|
| 研发人力 | 学生团队为主，人力成本显著低于商业公司 | 固定，优势项 |
| 算力与仿真软件 | 模型推理与批量仿真的 GPU 算力；优先使用学校集群与学生优惠云资源；仿真器许可按合规清单采购 | 可变，随评测任务量增长 |
| 真机与耗材 | 桌面级协作机械臂、移动底盘、传感器与标定耗材；优先向合作厂商借测 | 一次性为主，验证期集中投入 |
| 数据与标注 | 任务集构建与失败原因人工标注（诊断准确率的真值来源） | 验证期集中投入，是核心资产形成成本 |
| 知识产权与合规 | 软件著作权、专利申请、科技查新报告、许可合规审查费用 | 一次性，金额可控 |
| 社区与市场 | 开源社区运营、学术会议与宣讲、标杆合作与评测榜单运营 | 可变，早期以社区与标杆为主 |


### 9.2 三年发展规划与收入预期

| 年度 | 阶段定位 | 关键动作 | 收入预期 |
|---|---|---|---|
| 第 1 年 | 技术验证与滩头突破 | 完成单仿真器 + 单本体的规划—验证—修复闭环；开源内核发布；拿下 3–5 个高校实验室种子用户；申请专利与软著 | 【待填：以开源获客与经费支持为主，收入不作激进假设】 |
| 第 2 年 | 产品化与规模复制 | 评测云平台上线并开始订阅收费；完成第二个仿真器与第二类本体的适配；与 1–2 家整机厂商或创新中心开展试点 | 【待填】 |
| 第 3 年 | 标准建立与横向扩张 | 推动评测协议成为创新中心或地方标准的参考；提供标准化测评服务；拓展企业版私有化部署 | 【待填】 |


### 9.3 单位经济模型（关键假设）

| 指标 | 取值 | 说明与依据 |
|---|---|---|
| 单席位年度收入 | 【待填】元 | 平台订阅 + 私有化摊销 + 评测服务分摊 |
| 单席位边际成本 | 【待填】元 | 算力与存储为主，软件边际成本近零；需区分云订阅与私有化两种口径 |
| 毛利率 | 【待填】% | 平台层与服务层毛利显著高于硬件相关成本，需扣除算力与真机验证成本后测算 |
| 获客成本 | 【待填】元 | 以开源社区、学术会议与标杆案例为主，需给出测算依据 |
| 客户生命周期 | 【待填】年 | 订阅制；需给出续费率假设，并说明高校客户与厂商客户的差异 |
| 单客户生命周期价值 | 年度收入 × 毛利率 × 生命周期 | 由上述假设推导 |
| 回本周期 | 【待填】月 | 获客成本 ÷ 月均毛利 |

财务部分的写作纪律：把"哪些是假设、哪些是实测"标注清楚；在校赛与省赛阶段，收入预期宁可保守，而把重点放在"单位成本优势"与"资产可复用"这两点上，因为它们才是学生项目真正的说服力所在。

## 第十章  团队

本章对应商业计划书的"团队介绍"章节、PPT 的第 10 页。


### 10.1 团队构成

核心成员 7 人，可根据实际情况在 6–8 人之间调整。人数偏少并非妥协，而是"通用能力使用成熟开源组件、创新火力集中于技能抽象与验证闭环"这一技术策略的直接结果——把有限人力集中投在最能形成差异化的环节。小团队采用一人多岗，个别角色可按需合并（见下表备注）。

| 组别 | 人数 | 核心职责 | 能力要求 | 负责人 |
|---|---|---|---|---|
| 规划与算法组 | 2 | 约束感知的任务分解、计划可满足性判定、失败模式诊断与修复策略、不确定度校准 | 任务规划、约束求解、大模型应用、Python | 【待填】 |
| 仿真与平台组 | 2 | 多仿真器适配、并行批量评测与任务调度、评测云平台与可视化回放、报告生成（平台与可视化部分可并入算法组） | 仿真工程、后端开发、数据库、前端可视化 | 【待填】 |
| 机器人与硬件组 | 1–2 | ROS 2 接入与真机联调、本体能力模型构建与参数标定、真机小样本验证（可并入仿真与平台组） | 机器人运动学、ROS 2、嵌入式与硬件调试 | 【待填】 |
| 数据与评测组 | 1 | 标准化任务集构建、六项指标实现与统计检验、失败原因人工标注、基准与榜单发布（★ 本项目的资产与公信力所在） | 实验设计、统计与数据分析、数据工程 | 【待填】 |
| 商业组 | 1–2 | 市场调研与用户访谈、商业计划书与答辩材料、财务测算、创新中心与检测机构对接 | 市场分析、文案与答辩、财务 | 【待填】 |
| 合计 | 7（区间 6–8） | — | — | — |
| 指导教师 | 2 位 | 一位把关具身智能与机器人方向（任务规划、运动学、仿真与评测方法），一位把关人工智能与软件工程方向（大模型应用、平台架构与工程规范）；协助资源协调、真机与试验条件对接 | 机器人学 / 具身智能 + 人工智能 / 软件工程 | — |

规模说明：核心成员 7 人，可按实际情况在 6–8 人之间调整，全队一人多岗、无冗余配置。挑战杯规则中团队人数上限与指导教师上限以官方通知为准，且每位学生仅可参与一个参赛项目。


### 10.2 团队优势（商业计划书中需正面陈述）

- 跨学科精干配置：7 人覆盖任务规划、仿真与平台工程、机器人真机、数据评测与商业五个方向，形成从语言任务到真机验证再到测评报告的完整闭环。其中"数据与评测"方向是本项目区别于纯算法团队的关键——没有评测协议与统计口径，就无法让任何人相信我们的结论。

- 一人多岗、决策链极短：小团队几乎没有沟通成本，从算法改动到仿真验证可在一小时内闭环，这种迭代速度是分工细密的大团队难以比拟的。

- 不做重复造轮子的技术策略：仿真器、运动规划、大模型全部使用成熟开源组件与官方接口，创新集中于技能抽象与验证闭环两个环节，把有限人力投在最有价值的环节——这正是 6–8 人够用的原因。

- 真机验证条件可控：真机验证只需小样本（用于标定仿真—真机相关性），可用桌面级协作机械臂在实验室内完成，不依赖昂贵的人形或四足本体，也不需要大额硬件投入。

- 成本优势：学生团队的人力成本结构使我们能够以显著低于市场方案的价格切入，并仍保持健康的毛利水平。


### 10.3 团队风险与应对（建议主动说明）

风险：团队仅 6–8 人，而项目要求"任务规划与约束求解 + 机器人运动学与仿真 + 大模型应用 + 平台工程"的复合能力，人力密度要求高；一旦核心成员因学业或参赛冲突退出，将直接影响进度。此外，真机资源与仿真算力若不能及时到位，P3 阶段的迁移性验证会受阻。

应对：① 以"通用能力用成熟组件、创新集中于技能抽象与验证闭环"的策略压缩工程量；② 关键模块（技能表示、能力模型、诊断规则、评测脚本）做到文档化与脚本化，避免能力集中于单点；③ 真机验证用小样本 + 借测 + 合作实验室的方式分担，不把关键路径押在自有硬件上；④ 算力优先使用学校集群与学生优惠云资源，把付费算力留到必要环节；⑤ 两位指导教师分别把关机器人方向与 AI 方向，在方法层面提供兜底。

### 11.1 五阶段技术路线图

| 阶段 | 时长 | 交付物 | 可演示状态 |
|---|---|---|---|
| P0 调研与需求锁定 | 2 个月 | 仿真器与基准盘点、厂商与实验室访谈、复现公开规划方法并统计"语义合理但物理不可行"的占比、技能与任务集初版、仿真器许可合规清单 | 需求报告与取证材料 |
| P1 单仿真器 + 单本体 MVP | 3 个月 | 技能抽象 v0、本体能力模型、单仿真器适配、开环规划基线、可执行性判定与报告输出 | ★ 可现场演示：一次规划 → 仿真验证 → 报出不可行原因 |
| P2 验证—诊断—修复闭环 | 3 个月 | 失败模式诊断、反例约束回灌、三级修复策略、并行批量评测、失败模式库 | ★ 闭环录屏：失败 → 诊断 → 自动修复 → 通过 |
| P3 跨本体与迁移性 | 3 个月 | 第二个本体接入与技能复用率实测、第二个仿真器适配、域随机化评测、真机小样本相关性分析 | ★ 答辩杀手锏：跨本体复用数据 + 仿真—真机相关性 |
| P4 产品化与推广 | 2 个月 | 评测云平台、报告与榜单、开源发布、软著与专利、种子用户与标杆合作、参赛材料定稿 | 完整产品与材料包 |

资源紧张时的取舍原则：优先保 P1 的可演示闭环与 P3 的跨本体与迁移性数据，因为前者决定"能不能现场演示"，后者决定"有没有最硬的证据"。P2 的修复策略可先降级为规则级的简单回灌，把算法复杂度留到后续版本。

## 第十二章  风险与应对

本章对应商业计划书的"风险分析"章节。写作要求：主动暴露风险并给出应对，比宣称"没有风险"更可信，也是评审关注团队成熟度的重要观察点。

| 风险类别 | 具体风险 | 应对措施 |
|---|---|---|
| 技术风险 | 大模型的任务分解在长程任务上仍不稳定，约束解码可能降低生成多样性 | 采用"约束预筛 + 候选采样"的组合：先用能力模型排除明显不可行，再在可行域内保留多个候选；如实报告未找到可行计划的情形；把长程任务拆成可独立验证的阶段 |
| 技术风险 | 仿真器适配工作量大，接口变动可能造成返工 | 把适配层做成薄适配器并隔离版本差异；优先支持 2 个仿真器（一个 GPU 并行、一个轻量），不追求覆盖全部；用接口测试用例保障升级不破坏回归 |
| 技术风险 | 失败模式诊断准确率在复杂场景下不达预期 | 先用规则化物理判据覆盖主要失败类别（不可达 / 碰撞 / 抓取失败 / 前置不满足 / 超时），再用轨迹特征做细分；诚实报告各类别的准确率与混淆矩阵 |
| 数据风险 | 标准化任务集与失败标注数据稀缺，人工标注成本高 | 以少量高质标注 + 公开任务集迁移为基础；通过开源社区回流任务与失败案例；用主动学习优先标注高价值样本 |
| 验证风险 | 仿真—真机相关性需要真机数据，而真机资源不稳定 | ★ 这是创新点四的前置条件，必须最早启动；以桌面级小样本 + 借测方式开展，不依赖大规模真机部署；如实报告相关性分析的样本量与置信区间 |
| 标准与生态风险 | 评测协议的公信力需要时间积累，社区未必采用我们的格式 | 与创新中心、检测机构共建而非单方面发布；把内核开源、把协议做成可导入导出的开放格式，降低采用门槛；优先争取一个标杆机构的使用案例 |
| 合规风险 | 仿真器与模型的许可条款差异大，商用场景存在授权风险 | 建立许可合规清单并逐项核对，在文档与产品中明确标注各组件的许可与使用边界；提供完全离线的本地部署模式，避免数据出境与联网依赖 |
| 市场风险 | 头部生态方（如仿真平台厂商）或整机厂商自行补齐规划验证与评测层 | 以"中立性"与"社区资产"（技能库 + 失败模式库 + 协议）建立壁垒；在 12–18 个月内绑定高校与创新中心的使用习惯；主动与大厂生态做适配而非对抗 |
| 市场风险 | 高校与实验室预算有限，付费转化慢于预期 | 采用开源内核 + 分层收费：先以免费层获客，把付费点放在"批量评测算力"与"标准化报告"上；优先争取有专项经费的创新中心与检测机构 |
| 团队风险 | 仅 6–8 人，跨领域能力要求高，核心成员退出影响进度 | 关键模块文档化与脚本化，避免能力集中于单点；两位指导教师分别把关机器人方向与 AI 方向；以"通用能力用成熟组件"压缩工程量 |
| 赛事风险 | 赛道选择与材料要求变化 | 第一时间向学校团委确认赛道、类别与截止时间；同时准备技术材料（大挑）与商业材料（小挑）以适配不同赛道 |
